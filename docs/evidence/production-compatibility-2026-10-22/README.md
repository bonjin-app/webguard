## Reproduced execution failure

Two distinct classic scripts under the same High seed `19` generated a global `_0x48c0` helper. The first exported callback returned `first private price 107:41` before loading the second file, then threw `TypeError: …charAt` afterward. [RED receipt](classic-collision-red.json), [first source](collision-fixtures/first.source.js.txt), [second source](collision-fixtures/second.source.js.txt) and both protected `.txt` files retain the controlled fixture. These are synthetic values, not application/customer data.

Explicit unique prefixes were a passing control. Automatic namespaces now provide that separation centrally without changing application globals or weakening High. Fixed seeds retain reproducibility for the same source/options/filename; seed zero receives an independent namespace. The fingerprint is not an authenticity primitive. The [upstream engine documents the cross-file collision mechanism](https://github.com/javascript-obfuscator/javascript-obfuscator#identifiersprefix).

The new regression exercises delayed callbacks after subsequent script loading with fixed and randomized seeds, public globals, and Node/browser namespace consistency. The original CI startup timeout did not preserve its failing generated files and remains unattributed; this separate reproduction must not be described as proof of that old failure's cause.
