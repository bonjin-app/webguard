# SDK 적용 흐름과 공개 문서 구성 개선 · 2026-10-22

SDK가 주 제품이고 웹은 적용·검증을 체험하는 공간이라는 기준으로, 설정 검증부터 설치·가이드·소비자 프로젝트 검증을 연결했습니다. npm 게시는 계속 보류하며 기존 배포 후보를 교체하지 않았습니다.

## 수정한 내용

1. **보호 설정의 의도치 않은 약화 차단.** Core `resolveConfig()`가 상속된 `obfuscation`·`integrity`를 읽거나 getter를 반복 평가하여 Strict 보호를 끌 수 있었습니다. 루트와 각 하위 설정을 자체 데이터 속성으로 복사한 뒤 검사합니다. 사용자 정의 프로토타입·접근자·알 수 없는 심볼/숨김 키는 거부합니다. 문자열 목록의 빈 슬롯·접근자·사용자 정의 반복자·추가 속성도 거부하며, 일반/null 프로토타입 데이터와 명시적 `false`는 유지합니다. 신뢰할 수 없는 JavaScript 설정 파일을 실행하는 샌드박스는 아닙니다.
2. **설치 안내의 공개/내부 경계 정리.** README의 첫 설치 명령을 실제 미게시 후보 파일 설치로 바꾸고 소비자 Vite·브라우저 SDK 예제는 공개 패키지 진입점으로 통일했습니다. 저장소 전용 CLI는 별도로 표시합니다. 한국어 가이드에 설정 입력 검증을 추가하고, 첫 화면의 기술 메모는 문제 해결 절로 이동했습니다.
3. **읽을 수 있는 전체 가이드.** 설치·환경별·SSR 문서를 목차·코드·표·문서 사이 탐색이 있는 같은 파란색 HTML 화면으로 생성합니다. 로컬 `.md` 링크를 공개 문서와 저장소 파일 링크로 연결하고 원문 `.txt` 다운로드는 유지합니다. 렌더러는 현재 문서의 Markdown 부분 집합만 지원하고 HTML은 텍스트로 이스케이프합니다. 빈 목록 항목에서 빌드가 멈추는 문제도 제한 시간이 있는 회귀 시험으로 재현·수정했습니다. 생성 페이지는 스크립트 없이 읽으며 실제 SDK 제어 UI는 대화형 문서 홈·데모에 있습니다.
4. **설치한 패키지의 검증을 CI에 연결.** `pnpm test:consumers`는 임시 위치에 패키지를 한 번 만들고 동일한 바이트를 새 Vite 7/8, Webpack/esbuild/일반 HTML, Next 프로젝트에 설치합니다. SSR 템플릿은 별도의 작업 공간 빌드 검증이며 tarball 설치 검증으로 세지 않습니다. 실행한 검사·실패·제외 항목을 JSON으로 남기고 보류 후보의 전후 해시를 비교합니다. CI 구성은 추가했으며 GitHub Actions 원격 실행 성공을 주장하지 않습니다.
