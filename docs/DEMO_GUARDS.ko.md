# WebGuard 데모의 보호 기능과 확인 방법

공개 체험: https://webguard.uulab.co.kr/demo

`전체 기능 체험 시작`은 SDK 정책, 정책 스위치 비교, 배포 호환성, 보안 시나리오, 배포 리소스 검사와 High 난독화 비교를 실행합니다. 키보드·우클릭은 화면의 본문 시험 영역에서 직접 조작합니다. 각 결과는 실제 관측값이며 미지원·시간 초과·네트워크 실패는 차단 성공으로 집계하지 않습니다. 공개 데모는 로컬 0.3.0 후보 기능을 체험하며, npm 최신 버전은 0.2.0입니다. 0.3.0 npm 게시는 보류 중입니다.

## 켜기·끄기로 보호 전후 비교

1. [정책 켜기·끄기](https://webguard.uulab.co.kr/demo#policy-lab)에서 네트워크·DOM 문자열 삽입·인라인 스크립트 제한을 선택합니다.
2. `선택 정책 비교 실행`을 누르면 매번 새 격리 프레임 두 개로 같은 시험을 실행합니다. 왼쪽은 모두 끈 상태, 오른쪽은 선택한 설정의 실제 결과입니다.
3. `정책 모두 끄기` 또는 개별 체크박스를 바꾸고 다시 실행해 허용·차단 차이를 확인합니다. 설정 변경 즉시 이전 결과는 무효화됩니다. 본문이나 서버 전체의 정책이 변경되는 것은 아닙니다.
4. [실시간 SDK 체험](https://webguard.uulab.co.kr/demo#live-demo)의 입력 제한 버튼을 켜거나 끈 뒤 본문 시험 영역에서 F12·우클릭을 직접 비교합니다. 파일 무결성 검사도 개별적으로 끌 수 있습니다.

[배포 호환성 검사](https://webguard.uulab.co.kr/demo#compatibility-lab)는 실제 한글 하위 페이지, UTF-8 선언 위치, CSP 메타·응답 헤더, 경로 이동의 최종 주소·쿼리, 고정 HTTP API와 없는 경로의 404를 검사합니다. 화면은 브라우저가 실제로 따라간 이동을 확인하며 중간 상태 코드를 추측하지 않습니다. 공개 HTTP API 연결은 Vite preview 프록시 검증과 별개입니다. `하위 페이지 직접 열기`로 한글 화면을 직접 확인할 수 있습니다.

| 체험            | 실제 확인 대상                                       | 범위                                |
| --------------- | ---------------------------------------------------- | ----------------------------------- |
| SDK 실시간 설정 | 옵션 변경 후 키·우클릭 이벤트 취소 여부              | 페이지가 전달받는 이벤트만 제한     |
| 스크립트 삽입   | 인라인 스크립트·eval·HTML 핸들러의 실행 전후         | 격리 프레임의 CSP 정책              |
| 파일 변조       | 원본·변조본의 SHA-384 차이                           | 로컬 해시 비교                      |
| 서버 가격 검증  | 정상 요청 200, 변조 요청 409 및 서버 계산 가격       | 상태를 저장하지 않는 서버 검증 예제 |
| 네트워크 전송   | 고정 시험 API의 응답과 connect-src 위반              | 격리 프레임의 fetch 제한            |
| DOM 삽입        | innerHTML 삽입과 Trusted Types 강제 정책의 TypeError | 지원 브라우저에서만 확인            |
| 배포 리소스     | 원본·환경·설정·보고서·소스맵 URL의 실제 404          | 공개 파일 허용 목록                 |
| 배포 JS 무결성  | HTML의 SRI와 실제 내려받은 JS의 SHA-384              | 해당 배포 파일의 일치 여부          |
| 난독화          | 원본과 보호 코드의 실제 실행 결과 비교               | 브라우저의 격리 실행 예제           |

## 데모 자체의 배포 코드

Playground의 진입 JS에는 WebGuard Vite 플러그인의 `strict` 프리셋을 적용합니다. High 난독화, RC4 문자열 인코딩, 제어 흐름 변환을 사용하고 공개 소스맵을 생성하지 않습니다. HTML의 JS·CSS에는 실제 파일 기준 SRI를 붙입니다. 대용량 외부 난독화 엔진과 워커는 기존 빌드 산출물을 사용하며, 자체 앱 코드만 추가 난독화합니다. 법적 고지 파일은 공개를 유지합니다.

브라우저가 실행하려면 JS·CSS를 내려받아야 하므로 Network·Sources에서 전달된 파일 자체를 숨길 수는 없습니다. 원본 저장소 파일·소스맵·서버 설정을 배포 대상에서 제외하고, 전달되는 코드는 분석 비용을 높이는 방식으로 보호합니다. 난독화는 암호화된 비밀 저장소나 서버 권한 검증의 대체 수단이 아닙니다.

## 격리된 정책 체험

시험 프레임은 `sandbox="allow-scripts"`를 사용하고 동일 출처 권한을 주지 않습니다. 고정된 무해한 시험 코드만 실행하며, 사용자 편집 내용은 이 프레임에 삽입하지 않습니다. 응답은 프레임 식별자·무작위 토큰·출처·값 구조를 검사한 뒤 받습니다. 프레임은 완료·시간 초과 후 제거합니다.

네트워크 시험 API `/api/demo/network-probe`는 `{ "probe": "webguard-network-ok" }`만 반환합니다. 격리 프레임에서 대조군 응답을 읽기 위해 이 상수 응답에만 CORS `*`를 사용합니다. 인증 정보나 사용자 데이터를 반환하지 않으며 요청은 `credentials: "omit"`으로 보냅니다. 가격 API의 동일 출처 제한은 유지됩니다.

0.3.0 후보의 `webguardApp()`은 빌드 HTML에 CSP 메타 정책을 자동 추가합니다. HTTP 전용 정책과 서버 권한 검증은 배포 환경에서 별도로 설정해야 합니다. Playground 본문에는 격리 체험을 위한 정책을 유지하므로, 시험 프레임의 엄격한 정책이 본문 전체에 적용된다고 해석하면 안 됩니다.

## 격리 실행의 시작 시간과 실행 시간

프레임·Worker 준비와 사용자 코드 실행은 별도로 제한합니다. 시작 단계는 최대 5초 동안 준비 완료 신호를 기다리고, 준비된 Worker에 실행을 요청하기 직전에 기존 1,000ms 실행 예산을 시작합니다. 프레임의 실행 응답이 사라지면 부모의 별도 1,800ms 감시가 정리합니다. 준비되지 않은 Worker는 `Sandbox startup timed out`, 실행 중 한도 초과는 `Execution timed out`으로 구분합니다. 브라우저 타이머는 스케줄링 지연을 받을 수 있으므로 하드 실시간 보장은 아닙니다.

기존 WebKit 실패는 Worker 생성 직후의 대기 시간이 실행 예산에 포함된 문제였습니다. 실제 Worker 시작을 1.4초, 프레임 시작을 2.1초 늦추는 회귀로 재현했습니다. 준비 완료 확인 후 실행하는 방식은 원래의 격리 출처·CSP·네트워크 제한을 유지하며 `eval` 허용을 추가하지 않습니다. 중복 준비 메시지는 실행 시간을 연장하지 못하고, 오류·취소·페이지 이동 시 Worker·Blob URL·타이머·포트를 정리합니다. 메시지가 비어 있는 예외도 실패로 표시하며 성공으로 계산하지 않습니다.

## 예상된 콘솔 진단

CSP·Trusted Types 시험은 브라우저의 정책 위반 진단을, 가격 변조는 HTTP 409를 의도적으로 발생시킵니다. 비공개 URL 검사는 HTTP 404를 기대합니다. 시험 대상과 실제 상태를 화면에 표시하며 콘솔 기록을 숨기지 않습니다. 일반 화면 로딩의 404·5xx·처리되지 않은 예외는 예상된 시험 결과와 구분해야 합니다.

개발자도구 창은 브라우저 사용자가 제어합니다. 단축키 제한, 도킹 크기 기반의 추정 이벤트, 난독화로 창 자체를 잠그거나 사용자 소유 브라우저의 모든 실행을 통제할 수는 없습니다.
