# WebGuard 품질 개선 — 0.2.0

승인 범위: 범용 SDK의 완성도를 높이고 실제 코드·테스트·예제·배포 패키지에 반영한다. Codex 설정은 변경하지 않는다.

## 설계

- `webguard-check dist --url https://site.example/`와 Node 전용 `uulab-webguard/verify` API를 제공한다. 신뢰된 로컬 빌드의 매니페스트·헤더 정책을 먼저 검증한다. 원격 매니페스트를 신뢰하지 않는다.
- 실제 첫 화면, 파일, 소스맵·제어 파일의 응답을 검사한다. 각 파일의 크기와 SHA-384를 비교하고 생성된 헤더 값과 실제 헤더를 비교한다. 없는 경로는 404/410이어야 한다. SPA 폴백 200도 실패다.
- 요청별 제한 시간, 스트림 해시, 기대 크기 초과 시 취소, 요청 실패의 항목별 보고로 검사 도구 자체가 멈추거나 무한히 메모리를 쓰는 일을 방지한다. 모든 경로는 네트워크 요청 전에 검증한다.
- SDK는 Shadow DOM 편집 영역을 보존하고 종료·무결성 비활성화 시 진행 중인 무결성 요청을 취소한다.
- Vite의 실제 출력 위치가 보호 후처리 경로와 다를 수 있는 설정은 명확하게 거부한다.
- npm 게시 자체를 재시도하지 않는다. 성공 후 레지스트리 확인만 제한적으로 재시도하고 무결성 충돌은 즉시 실패한다.

## 검증

각 동작의 실패 재현 후 회귀 테스트를 추가한다. 전체 빌드·타입·린트·단위/통합 테스트, 설치한 tarball의 실제 CLI·타입·브라우저 동작, 기존 데모의 브라우저 회귀를 확인한다. npm 게시와 공개 데모는 별도 공급자 확인으로 기록한다.

검사 성공은 이 빌드의 파일·헤더·지정한 노출 경로가 관측 시점에 일치한다는 뜻이다. 서버 인증·권한·API 입력·DDoS 또는 브라우저 소유자의 디버깅을 완전히 차단한다는 뜻은 아니다. 헤더 비교는 공백을 정규화한 생성 값의 일치 검사이며 CSP의 모든 의미적 동등성을 판정하지 않는다.

## 완료 결과

0.2.0을 npm에 공개하고 다운로드한 패키지 해시와 `latest`를 확인했다. 실제 레지스트리 설치 후 Vite 7·8의 타입·빌드·SDK·배포 검사 명령이 통과했다. 로컬 239개 단위/통합 테스트와 54개 브라우저 테스트, 공개 HTTPS 데모의 35개 검사를 통과했다. 공개 파일 27개와 가이드의 바이트가 준비한 산출물과 일치한다. 이전 배포 기록은 유지했다.
