# WebGuard 프로덕션 후보 기준

목표는 지원하는 웹 환경에서 난독화·무결성·정책·가드의 실제 동작과 비용을 확인하고, 문제가 생기면 복구할 수 있는 **0.3.0 릴리스 후보**입니다. 이 문서나 자동 검사 통과만으로 정식 안정 버전을 승인하지 않습니다. npm 게시는 보류 중입니다.

## 단계와 승인 기준

| 단계           | 필수 근거                                                         | 승인 범위                           |
| -------------- | ----------------------------------------------------------------- | ----------------------------------- |
| 자동 검증 후보 | 아래 자동 기준을 같은 소스/패키지로 통과                          | 지원 예제에서 반복 검증 가능한 후보 |
| 운영 파일럿    | 실제 적용 앱의 스테이징·업무 시나리오·성능 예산·복구 훈련         | 해당 앱에 한정한 제한 도입          |
| 정식 안정 버전 | 파일럿 결과·실제 기기 근거·독립 보안 검토·지원 범위와 릴리스 승인 | 승인한 버전·환경에 한정한 안정 지원 |

현재 확보한 자동화 근거를 고객 앱·실제 기기·외부 검토 결과로 대체해서 기록하지 않습니다. 미확보 항목은 **대기**입니다. 개발자도구 강제 종료나 전달한 소스의 완전 비공개는 어느 단계에서도 승인 대상이 아닙니다.

## 자동 기준

1. **소스와 배포 식별:** 커밋, SDK/설치 패키지 해시와 브라우저 버전을 기록합니다. 고정 CDN 파일은 바꾸지 않고 새 릴리스를 추가하며, 보류된 npm 파일을 보존합니다.
2. **기본 검사:** `pnpm verify`, `pnpm format:check` 통과. 네 언어 README의 링크·예제·실제 API 타입이 일치해야 합니다.
3. **실제 설치:** `pnpm test:consumers`로 같은 임시 tarball을 새 Vite 7/8·Webpack·esbuild·HTML·Next 프로젝트에 설치합니다. SSR 템플릿은 워크스페이스 빌드 검증으로 별도 표시합니다. 누락된 런타임은 성공으로 계산하지 않습니다.
4. **브라우저와 복구:** `pnpm test:e2e`에서 Chromium·Firefox·WebKit의 앱 실행·가드 ON/OFF·무결성·UI 복구를 확인합니다. 모달 교체 중 해제/정책 변경, 재진입 초기화와 반복 수명 주기의 회귀 검사가 필요합니다. CDP 전용 검사의 다른 엔진 제외는 명시합니다.
5. **반복 수명 주기:** 반복 초기화·업데이트·해제 후 입력 제한·모달·소유 리소스가 남지 않아야 합니다. 실제 타이머 표본과 합성 pagehide/pageshow 검사를 구분하며, 이를 실제 BFCache나 수 시간 안정성으로 표현하지 않습니다.
6. **성능과 크기:** `pnpm benchmark:browser --budget benchmarks/react-vite-budget.json`는 같은 소스를 실행 시점에 보호 전후로 각각 빌드하고 실제 정책을 적용한 뒤 비교합니다. 워밍업과 교대 표본, 빌드 시간과 브라우저 실행 비용을 분리합니다. 유지하는 예제의 전송 크기 예산을 초과하면 실패하고, 타이밍·힙 관측은 호스트 의존 측정으로 남깁니다. 난독화 강도를 몰래 낮추지 않습니다.
7. **JSP/Java:** `mvn -B -f examples/jsp-servlet/pom.xml -Dwebguard.browser=true package`로 JSP 컴파일·Servlet HTTP·세 브라우저의 SDK 동작을 검증합니다. 실제 운영 Tomcat 배포와는 구분합니다.
8. **의존성:** 고정 lockfile 설치 후 `pnpm audit --prod`를 실행합니다. 알려진 취약점이 보고되면 검토·해결 전 승인하지 않습니다. 레지스트리 조회 실패와 알려진 항목 0개는 서로 다르며, 0개가 취약점 부재 증명은 아닙니다.
9. **공개 배포:** 실제 서비스에 올린 경우에만 신뢰한 로컬 최종 바이트·HTTP 헤더·SRI·비공개 경로를 공개 URL에서 다시 대조합니다. 소스 CI 통과만으로 공개 사이트 반영을 주장하지 않습니다.

## 실제 적용 앱에서 남은 기준

- **업무 흐름:** 로그인·로그아웃·결제 완료/취소·폼·라우팅·동적 import·SSR hydration·오류 화면을 보호 전후 비교합니다. 사용하지 않는 기능은 적용 앱의 범위에서 제외했다고 기록합니다.
- **사용자 환경:** 대상 Chrome/Edge/Safari/Firefox의 실제 버전과 모바일 실제 기기를 확인합니다. 자동화 WebKit을 물리 Safari로 기록하지 않습니다.
- **성능:** 대상 기기·네트워크에서 초기 상호작용·청크 전송량·장시간 메모리·배터리 영향을 측정하고 앱 소유자가 예산을 정합니다. 저장소 예제의 예산을 고객 앱의 SLA로 재사용하지 않습니다.
- **장시간과 재방문:** 실제 세션·탭 전환·화면 잠금/복귀·BFCache·반복 내비게이션을 포함한 파일럿 결과를 남깁니다. 짧은 반복 검사를 장시간 결과로 대체하지 않습니다.
- **독립 검토:** 외부 또는 별도로 책임을 지는 보안 검토자가 위협 경계·경로 처리·무결성 신뢰 기준·의존성·복구를 검토하고 잔여 위험을 기록합니다. 개발 에이전트의 코드 리뷰는 이 승인을 대체하지 않습니다.
- **릴리스 승인:** 지원 버전·문제 접수 경로·호환성 변경·롤백 산출물을 확인하고 운영 책임자가 승인합니다. 이 승인 전에는 정식 프로덕션급이라는 문구를 사용하지 않습니다.

## 실행과 결과 읽기

```sh
pnpm install --frozen-lockfile
pnpm verify
pnpm format:check
pnpm exec playwright install chromium firefox webkit
pnpm test:e2e
pnpm test:consumers
pnpm benchmark:browser --budget benchmarks/react-vite-budget.json --evidence test-results/rc/browser-performance.json
pnpm audit --prod
```

각 명령이 성공했는지와 그 명령의 근거 범위를 함께 읽습니다. `pnpm test:consumers`는 npm에 게시하지 않으며, `release:prepare`·`release:publish`는 이 후보 검증 절차에 포함하지 않습니다. [지원과 업데이트·롤백](SUPPORT.md), [위협 모델](../THREAT_MODEL.md), [보안 제보](../SECURITY.md)를 함께 확인하세요.
