Python · SSR에 WebGuard 적용하기

내 서버의 브라우저 JavaScript를 보호하는 순서입니다. 서버 언어·템플릿 자체는 난독화하지 않습니다. 저장소 예제 실행은 맨 아래에 따로 있습니다.

준비 사항

  • 빌드 머신: Node 22.12 이상, npm. 서버 요청마다 Node를 실행하지 않습니다.
  • 서버: Python 3 및 기존 WSGI/ASGI 애플리케이션.
  • 기존 앱을 백업하고 인라인 JS를 외부 파일로 옮깁니다. 인증·권한 검증은 기존 서버에서 유지합니다.

1. 설치

다운로드 화면에서 빌드 도구 패키지 .tgz를 받아 적용할 프로젝트 루트에 uulab-webguard-0.3.0.tgz로 저장합니다. 그 폴더에서 실행하세요. 

npm install --save-dev ./uulab-webguard-0.3.0.tgz

다운로드 대신 화면의 고정 URL 설치 명령을 그대로 복사해도 됩니다. npm 게시는 보류 중이므로 npm install uulab-webguard로 이 후보가 설치된다고 가정하지 마세요.

2. 클라이언트 JS와 서버 HTML 템플릿 수정

프로젝트 루트에 webguard-src/ 폴더를 만들고 보호할 앱 JS를 webguard-src/app.js로 옮깁니다. SDK 파일은 아래 빌드 파일이 설치된 패키지에서 자동으로 복사합니다.

webguard-src/init.js를 새로 만듭니다.

window.webguard = WebGuardSDK.WebGuard.init({
  devtools: { blockShortcuts: true, blockContextMenu: true },
});

서버 HTML 템플릿에서는 SDK → init → app 순서로 외부 스크립트를 불러옵니다. 아래 빌드 후 출력되는 태그 3개를 기존 앱 스크립트 대신 넣으세요. 다른 앱 파일이 있다면 같은 방식으로 추가합니다.

3. 빌드·실행

프로젝트 루트에 scripts/ 폴더를 만들고 다음을 scripts/webguard-assets.mjs로 저장합니다. TARGET은 기존 서버의 정적 파일 폴더이며 ASSET_BASE는 브라우저에서 사용하는 URL입니다. 실제 서비스 경로에 맞춰 두 값을 확인하세요. 

import { copyFile, mkdir, readFile } from "node:fs/promises";
import { constants } from "node:fs";
import { dirname } from "node:path";
import { createRequire } from "node:module";
import { createHash } from "node:crypto";
import { protectDirectory } from "uulab-webguard/build";

const require = createRequire(import.meta.url);
const SOURCE = "webguard-src";
const OUTPUT = "webguard-built";
const TARGET = "static/webguard";
const ASSET_BASE = "/static/webguard";
const files = ["webguard.global.js", "init.js", "app.js"];

await copyFile(
  require.resolve("uulab-webguard/browser.global.js"),
  `${SOURCE}/webguard.global.js`,
);
await protectDirectory(SOURCE, {
  output: OUTPUT,
  privateArtifactsDir: ".webguard-private/maps",
  config: { preset: "strict" },
});
await mkdir(dirname(TARGET), { recursive: true });
await mkdir(TARGET);
for (const name of files) {
  const bytes = await readFile(`${OUTPUT}/${name}`);
  await copyFile(
    `${OUTPUT}/${name}`,
    `${TARGET}/${name}`,
    constants.COPYFILE_EXCL,
  );
  const sri = "sha384-" + createHash("sha384").update(bytes).digest("base64");
  console.log(
    `<script defer src="${ASSET_BASE}/${name}" integrity="${sri}" crossorigin="anonymous"></script>`,
  );
}

프로젝트 루트에서 실행할 명령은 하나입니다.

node scripts/webguard-assets.mjs

출력되는 태그 3개를 위 공통 레이아웃에 붙입니다. JavaScript 파일만 공개 폴더로 복사하며 보고서·소스맵·원본은 공개하지 않습니다. webguard-src/webguard.global.js는 매번 SDK에서 생성하므로 직접 편집하지 마세요.

OUTPUT·비공개 맵 폴더·TARGET은 새 경로여야 합니다. 재빌드할 때 세 경로와 ASSET_BASE를 새 릴리스 경로로 함께 변경하세요. 기존 결과를 지우거나 덮어쓰지 않고 생성 후 검토합니다. 다른 앱 파일은 files와 공통 레이아웃에도 명시적으로 추가하세요.

Python 서버 예제의 POLICY["headers"]·응답 처리와 준비 코드의 정책 생성을 참고해 기존 미들웨어에 헤더를 연결하세요. 예제는 표준 WSGI이며 Django·Flask·ASGI의 자동 설치 플러그인이 아닙니다. 정적 파일을 Nginx가 직접 제공한다면 그 응답에도 별도로 같은 정책을 적용합니다.

기존 CSP에 동작 중인 외부 출처·nonce가 있다면 병합해 시험하세요. script-src 'self', object-src 'none', base-uri 'none', HTTP의 frame-ancestors와 nosniff가 기본 점검 대상입니다. 파일 교체 시 SRI도 갱신하고 릴리스별 URL 또는 재검증 캐시를 사용합니다.

이제 기존 서비스의 빌드·시작·배포 명령을 실행합니다. 난독화는 배포 전에 한 번 수행하며 매 HTTP 요청에서 수행하지 않습니다.

4. 정상 결과 확인

  1. 페이지의 기존 버튼·로그인·API가 이전처럼 동작해야 합니다.
  2. Network에서 JS 3개가 200, Sources에서는 변환된 JS가 보여야 합니다. 원본 소스맵이 공개되지 않아야 합니다.
  3. 콘솔에서 window.webguard가 생성되어 있고 SRI·CSP 로딩 오류가 없어야 합니다.
  4. 페이지가 전달받은 검사 단축키·우클릭을 제한하는지 확인합니다. 브라우저 메뉴나 이미 열린 개발자도구를 강제로 닫는 기능은 아닙니다.
  5. HTML·자산·API·오류 응답의 HTTP 헤더와 비공개 파일의 404를 확인합니다.

문제 해결

  • 앱이 실행되지 않음: 스크립트 순서·실제 URL·SRI를 먼저 확인하세요. CDN/프록시의 추가 JS 변환을 끕니다.
  • CSP 오류: 인라인 초기화·이벤트 속성을 외부 JS로 옮기고 기존 정책과 충돌하는 출처를 확인하세요.
  • 템플릿 경로 오류: 위 경로는 이 가이드의 예시입니다. 서비스의 컨텍스트 경로·정적 파일 매핑과 맞춰야 합니다.

선택: 저장소의 실행 예제부터 보기

아래는 패키지 설치 앱이 아닌 WebGuard 저장소 루트에서만 실행합니다. 저장소를 받은 뒤 Node 22.13 이상·pnpm 11로 pnpm install --frozen-lockfile을 먼저 실행하세요. 준비 스크립트와 서버 예제 원본은 .tgz에 포함되지 않습니다. 

pnpm build
node scripts/prepare-ssr-templates.mjs
python3 examples/ssr-templates/python/server.py --port 4190

http://127.0.0.1:4190/?name=홍길동을 엽니다. 인사·요청 ID가 서버에서 표시되고 카운터·서버 API 버튼이 작동해야 합니다. 이 서버는 개발용이며 운영에서는 기존 WSGI/ASGI 서버를 사용합니다.

실행 예제 상세에서 하위 경로와 검증 범위를 확인하세요.

WebGuard · 비밀값과 권한 검증은 서버에서 관리하세요.
