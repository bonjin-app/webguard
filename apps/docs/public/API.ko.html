설치 후 호출하는 공개 함수·옵션·반환값·오류·이벤트를 실제 패키지 export 기준으로 정리했습니다. 서비스명은 WebGuard이며 import·설치에 사용하는 패키지 식별자는 uulab-webguard입니다. 설치 → 환경별 적용 → 아래 함수 명세 순서로 확인하세요.

빌드·검증 함수와 타입

다음 11개 함수는 uulab-webguard/build에서 가져옵니다.

/verify의 checkDeployment는 출력 디렉터리의 정책·매니페스트를 읽어 배포를 검사합니다. /server의 createProtectedServer는 로컬 점검용 Node 서버를 반환합니다.

공개 설정·결과 타입은 WebGuardConfigInput, WebGuardConfig, Preset, SecurityHeadersOptions, TrustedTypesMode, DomIdentifierOptions, Finding, ProtectAppOptions, ProtectOptions, ProtectionReport, IntegrityManifest, DeploymentCheck에 정리했습니다.

연동·명령행

Vite의 webguardApp·WebGuardAppOptions, 저수준 webguard, Next의 withWebGuard·WebGuardNextOptions, ObfuscationLevel·StringArrayEncoding을 확인하세요.

실행 파일은 webguard, webguard-check, webguard-serve 세 개입니다. 각 명령의 인수·허용 옵션·출력·종료 코드를 따로 명시했습니다.

기본값과 지원 범위

진입점 기본 프리셋 SDK 자동 시작 디버깅 감지 기본
webguardApp strict 예 켜짐
withWebGuard strict 예 꺼짐
protectAppDirectory / protect-app strict 예 상세 옵션은 빌드 명세 참고
webguard, protectDirectory, resolveConfig standard 아니요 해당 없음
WebGuard.init 런타임 옵션 명세 참고 수동 명시적 정책에 따름

옵션 이름이 비슷해도 빌드 프리셋과 런타임 가드는 역할이 다릅니다. 난독화는 배포 전에 수행합니다. CDN SDK만 추가하면 기존 앱 소스까지 자동 난독화되지는 않습니다. 실행 중 update는 브라우저 정책만 바꾸며 이미 전달된 JS를 다시 변환하지 않습니다.

단축키 제한은 페이지에 전달되는 취소 가능한 입력에 적용됩니다. 브라우저 메뉴로 연 개발자도구 창을 강제로 닫거나, 콘솔 실행·Elements·전달된 자산을 완전히 숨기는 API는 없습니다. 디버깅 감지는 오탐·미탐 가능한 신호입니다. CSP·SRI·서버 헤더와 서버의 인증·인가·입력 검증을 함께 적용하세요. 보호 UI와 클라이언트 해시는 서버 보안 경계를 대체하지 않습니다.

문서와 버전 확인

이 문서는 현재 소스의 공개 API 계약입니다. npm 게시와 소스·다운로드 버전은 다를 수 있습니다. 설치한 package.json 버전과 동봉된 이 명세를 기준으로 사용하고, 다운로드에서 제공되는 버전을 확인하세요.

공개 export·SDK 메서드와 명세 앵커를 자동 대조합니다. 새 함수가 추가되면 명세 누락을 검증 오류로 처리합니다. 함수별 예제는 사용 흐름을 설명하며, 문서에 적힌 검사 범위를 넘어 모든 앱·브라우저의 실행 호환성을 보증하지 않습니다.

WebGuard · 비밀값과 권한 검증은 서버에서 관리하세요.
